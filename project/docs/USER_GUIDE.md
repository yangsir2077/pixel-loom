# Pixel Loom 使用手册

[返回 README](../README.md) · [English](../README.en.md) · [AI 使用指南](AI_GUIDE.md) · [发布说明](RELEASE.md)

一个让人和 AI 共用工程的本地像素画与动画编辑器。你可以手动画，支持 MCP 的桌面 AI 可以直接调用原生绘图工具，读取像素、检查图片、修改局部和导出素材。

本手册持续维护，当前软件版本与下载入口见 [README](../README.md) 和[公开发布页](https://github.com/yangsir2077/pixel-loom/releases)。Windows 桌面端已进行本机测试；提供可选无窗口后端与跨平台 CI 配置。尚未达到 Aseprite 的完整功能和成熟度。

## 检查更新

点击“更多 → 检查更新”，可手动查询新版、阅读版本说明，并打开 Windows 便携版下载或发布页面。桌面启动后会异步检查；发现新版在主界面显示可关闭的提醒，不打断编辑。自动检查成功后，24 小时内不重复查询；手动检查可随时执行。

可关闭“启动时检查更新”，或切换“包含公开测试版”。0.x 默认包含公开测试版。网络失败只在手动窗口显示说明，不影响绘画；发布页入口始终可用。检查仅请求公开 GitHub 版本信息，不上传作品、参考图、本地路径或客户端配置，偏好保存在用户数据目录。无窗口 MCP 不自动查询网络。

下载后先保存作品并退出软件及正在使用它的 MCP 服务，再用新版完整 `app` 文件夹替换旧版。保持原安装路径时，MCP 配置通常无需修改，更新后重新加载即可。此功能不自动安装或覆盖文件。

## 启动说明与支持作者

打开桌面应用会显示简短使用说明。**了解，进入**、Esc 或关闭弹窗均可直接使用；**打赏 UP 喝杯奶茶** 提供 5／10／15／20 元四个可选档位，选择后显示作者提供的对应微信收款图。打赏不影响任何功能，不检测付款，也不自动发起交易。“更多 → 使用说明与支持作者”可重新打开。收款图原始文件及金额映射位于 `pixel_workbench/resources/support/`。

## 开始使用

### Windows 便携版

**普通使用者优先选这一种，不需要另装 Python。**

1. 到[发布页](https://github.com/yangsir2077/pixel-loom/releases)，在 **Assets（资源）** 中选择 `pixel-loom-<版本>-windows-x64.zip`。
2. 完整解压，打开解压后的 `PixelLoom` 根目录，双击 **打开像素织机.cmd**；也可以进入 **app** 目录，双击 **PixelLoom.exe**。
3. 保留整个 `app` 目录：`PixelLoom.exe`、`PixelLoomMCP.exe` 和 `_internal` 必须放在一起。

```text
PixelLoom/打开像素织机.cmd       普通用户启动入口
PixelLoom/app/PixelLoom.exe      桌面编辑器
PixelLoom/app/PixelLoomMCP.exe   AI 客户端的 MCP 入口
PixelLoom/app/_internal/         必需运行库
```

如果已经进入 `app`，直接运行当前目录的 `PixelLoom.exe`。当前没有名为 `Pixel_workbench.exe` 的桌面入口；`pixel_workbench` 是源码模块名。`PixelLoomMCP.exe` 需要由 AI 客户端以 stdio 方式启动，手动双击不是打开编辑器的方法。

本地 AI 服务随软件启动，默认就绪。首次接入时，通过顶部 **更多 → MCP 首次接入配置** 复制本机配置，在客户端添加并重新加载 MCP。之后 AI 调用 `pixel_onboard` 即可读取工程、工具说明和操作流程，无需在软件中再次开启。

应用会按任务向 AI 提供对应说明：文字创作、图片转像素、局部修改、按需补齐和动画。制作先完成静态图与干净的可编辑物件层；转图保留自动底稿的尺寸、用色和合成效果。遮挡处没要求补齐时会保留未补状态，动画也需要另外提出。仅打开工程或导入参考，不会自动启动这些制作任务。

**更多 → AI 工作流与进度** 可按需查看当前记录和内置说明。记录不改画布，也不增加绘画版本；图层像素改动后，对应检查会失效并要求 AI 重看。AI 可以使用简要状态和未变图片复用来减少重复传输，仍需实际看图判断画面质量。

### git clone 后找不到 exe？

`git clone`、GitHub **Code → Download ZIP**、`*-source.zip` 和 **Source code** 都提供源码，不包含便携版的 `app` 和 exe。要直接使用，下载上面的 Windows 便携版；要从源码运行，按下一节安装。无需在克隆目录反复寻找或重命名 exe。

### 从源码安装

需要 Python 3.11+，桌面模式还需要 Tk（Windows 标准 Python 通常自带）。以下从克隆／源码 ZIP 解压后的仓库根目录执行；若当前目录已包含 `pyproject.toml`，跳过第一行：

```powershell
Set-Location .\project
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m pixel_workbench
```

Windows 也可以在 `project` 目录运行 `setup.ps1`，再双击同目录的 `打开像素织机.cmd` 或运行 `launch.ps1`。源码安装不会生成便携版的 `app/PixelLoom.exe`。Linux/macOS 同样先进入含 `pyproject.toml` 的源码目录，再在虚拟环境中安装、启动；桌面适配尚未完成完整验证。

从源码生成本机 MCP 配置（在含 `pyproject.toml` 的源码目录执行）：

```powershell
.\.venv\Scripts\pixel-loom-config.exe --format both
```

默认只输出配置，不修改其他应用。明确需要自动注册时使用 `--install codex`、`--install claude-desktop` 或 `--install both`；写入前保留原配置备份，并检查其他设置保持不变。

## 可视化工作台

### 项目保留与并排对照

顶部项目栏按固定编号显示当前展开的工程；名称前的编号不会因为切换而改变。项目列表来自本地记录，不是预设内容。

点击标签上的 **×** 可以收起标签；右键可关闭左侧、右侧或其他标签。关闭当前标签会先保存修改，再切到可用的相邻项目，没有其他可用项目时显示空白工作区。收起不删除工程文件、编号或历史版本，也不会放入“已删除”。

在 **项目 ▾ → 已收起的标签页** 或 **项目管理 → 已收起** 中选择项目，点击“重新打开所选”即可恢复原来的标签和编号。

点击顶部 **项目 ▾ → 项目管理**，可以添加已有 `.pixloom` 文件、打开、删除或恢复项目。新建、复制、历史版本和并排对照也在这个菜单中；没有项目时标签栏自动收起。按 Ctrl / Shift 多选后可批量删除；右键项目标签也可以删除单个项目。“已删除”保留工程文件、原编号和历史版本，恢复后可继续编辑。删除当前项目会先保存修改，再打开其他项目；删光列表后保持空白，重启不会重新添加已删除项目。普通删除不清理磁盘文件；彻底清理请在“已删除”中选择项目并预览范围后执行。

- 做行走、攻击等新动作时，先点击 **复制为新项目**，保留完整图层、动画与参考，新项目使用独立身份和文件路径。**＋ 新项目** 可创建空白工程。
- 点击项目名称即可切换；离开前自动保存当前修改，未命名的作品也会获得独立文件，避免被下一件作品覆盖。
- 点击 **并排对照**，选择两个工程，按各自真实帧时长同时播放、暂停或拖动时间检查。对照使用只读快照，不修改任何作品；“刷新快照”可读取最新修改。
- **版本记录** 自动保留 AI 每批修改（手动编辑按自动保存合并记录）。选择某一版可与当前效果并排播放、逐帧查看，点击“选用这版，继续修改”在同一个项目继续编辑；当前版与其他版本都会保留，并支持撤销。窗口打开后工程有新改动时，先刷新再选用。记录保存在本机用户数据目录，不会随单个 `.pixloom` 文件一起复制，也不会自动清除。若文件被外部程序改动，保存会拒绝直接覆盖。

项目目录、历史备份和编号记录保存在用户数据目录。移动电脑时，请同时备份项目文件及该目录。MCP 的 `pixel_projects` 提供列表、复制、新建、切换、历史、恢复和多项目图像对照；AI 的入门说明要求新动作先复制为独立项目。旧的 `pixel_project` 替换保护仍保留。

顶栏提供三个模式：**预览 → 截图反馈 → 手动修改**。预览模式收起左右侧栏，让画布使用整幅工作区；截图模式只显示可选标记工具和顶部截图工具栏；手动修改时才显示画笔、导航预览、图层、颜色和自动化工具。保存工程和导出始终在顶栏。

### 截图，直接发给 AI

1. 可选地在画布套圈、框选或画椭圆，标记需要关注的位置；也可以直接截整幅图。
2. 点击“截图并复制”。Windows 会自动复制图片，同时保存在本地 `feedback-captures` 目录。
3. 切到 AI 对话框按 Ctrl+V 粘贴，并说明希望修改的内容。不用在软件里填写或提交问题单。
4. 图片有“问题反馈图”标识、工程身份、版本、帧号和原始像素坐标；有标记时还会附局部放大。
5. AI 按[截图说明](../pixel_workbench/resources/FEEDBACK_IMAGE_GUIDE.md)识别用途，先查看对应区域；不清楚修改意图时在当前对话里询问用户。

原始 PNG 内含 `pixel_loom_feedback` 属性；聊天工具丢掉元数据时，可见标题和定位信息仍能识别。截图不改动作品、不创建新问题记录，也不自动发送消息。便携版附有“截图反馈给AI.md”；MCP 客户端可通过 `pixel_help(topic="feedback_images")` 读取同一说明。

旧工程的问题标注与问答仍然保留，入口在 **更多 → 旧版问题记录**。用户可以继续手动修改、保存与导出。

- 中间画布始终为主；手动修改时出现常用画笔，其他绘画与变换工具在“更多”中。
- 手动修改时，右侧分为“图层”“调色”“操作”三页；图层列表独立伸展和滚动，调色板不会挤走图层。帧时长与播放速度集中在底部时间轴，切回绘画时会记住上次使用的面板。AI 服务默认就绪；首次接入配置、协作记录和截图说明收在“更多”。
- 对称绘画支持左右、上下和四向；偶数宽度笔刷按实际像素镜像。多边形和曲线在提交前显示实际像素预览。
- 新建工程可选图标、角色和场景尺寸模板；调整画布与导出提供预览、尺寸和范围反馈。
- 底部时间轴显示缩略图、时长和播放位置；播放／暂停停留在正在观看的帧，继续播放从这里开始，独立的“停止”返回动作起点。“速度”可在 0.25×–4× 之间调节，仅影响预览，不改原始帧时长和导出；“逐帧总览”按页查看多帧。Ctrl+K 可搜索命令，F 适应画布，支持低于 100% 的全图预览和 12.5%／25%／50%／75% 缩放。网格、洋葱皮和参考叠加收在“视图”菜单。

拖动画布右侧分隔条可调整侧栏宽度，拖动画布与时间轴之间的分隔条可调整时间轴高度，布局保存在本机。切帧、选图层和选区操作不占绘画撤销记录，也不会清空重做。橡皮始终擦成透明像素；导入的多颜色 PNG 可在关闭“仅使用调色板颜色”时原色复制粘贴。

导出窗口使用打开时的工程快照。工程继续修改后会显示旧快照提醒；点击“刷新为当前工程”可更新快照与动作列表。无效导出参数会显示原因并禁用导出按钮。

“更多 → MCP 首次接入配置”生成的配置会携带当前应用的数据目录和工作区；使用自定义目录或隔离测试窗口时，复制这份配置才能让 AI 连到同一份工程。手动只填写 `--mcp` 会使用默认目录，不会自动继承另一个进程的启动参数。

选择“精灵表 + JSON”后，可在“图集格式”中选择：原生 JSON（默认，兼容原有读取方式）、Aseprite JSON Hash、Aseprite JSON Array 或 Godot 4 SpriteFrames。Aseprite 两种格式都保留完整像素帧、毫秒时长和动作标签，需使用目标引擎对应的导入器；它不是 `.aseprite` 工程。

选 Godot 4 后会同时得到 PNG、JSON 和 `.tres`。把 PNG 与 `.tres` 一起复制进 Godot 工程，将 `.tres` 拖到 AnimatedSprite2D 的 SpriteFrames 属性，选择动作即可播放；像素素材使用最近邻纹理过滤。动作的时长、反向／往返顺序、循环／单次要求会保留，无需安装插件。静态地形图仍需在引擎中设置 TileSet 网格。

Godot 默认的 PNG 导入选项 **Process → Fix Alpha Border** 可能调整半透明光晕、边缘的 RGB，导出的 PNG 本身不变。需要逐像素保留半透明颜色时，在 Godot 选中 PNG，在 Import 面板关闭该选项并 Reimport，再放到实际背景上查看；仅设置最近邻过滤不会关闭这项处理。本工具不会替你更改引擎工程的导入设置。

所有格式共用原来的审查与草稿规则。配套文件已存在时会提示确认覆盖；同名 `.tres` 存在时，请换文件名或选择 Godot 格式一起更新，避免旧资源引用新的不匹配图集。切换导出格式不修改原画，也不需要重复审查同一份已通过的内容。

### 自动化

切到 **手动修改 → 工具**，选择起伏循环、往返位移、批量时长、范围复制或批量描边。调整参数后先查看帧总览或按真实时长播放预览，再点击“应用到工程”。一次撤销可恢复整个批次。预览期间工程若被人或 AI 改动，旧计划会拒绝提交，需要重新打开流程。

起伏／往返流程从当前帧追加新帧，复制全部图层，只移动当前未锁定图层或选区。位移超出画布会裁切。它们适合呼吸、漂浮与物体移动；走路、攻击等姿态仍需要逐帧设计。GUI 对称是手绘辅助，MCP 操作仍按调用参数执行，不受界面开关影响。

### 法线与光照预览（0.7.19，按需使用）

“更多 → 法线与光照预览”打开独立窗口，平时不占画布。先导入同尺寸法线 PNG／对应帧图集，或新建平面法线；轮廓和高度图生成均为可调整的估算，不能恢复真实 3D 结构。普通图片不要把画死的亮暗直接当高度。

在效果图上拖动光源，调整环境亮度、光源高度、范围、法线和反光强度。左上切换“光照对照”“原图对照”“法线笔刷”；法线笔刷在左图画表面朝向，右图可同时看效果。发光图层从现有图层中选择，按原堆叠顺序合成，不会让底层光晕穿透不透明上层。玻璃仍需合适的透明度与边缘反射。

大画布可勾选“大图快速预览”降低交互计算量；精确检查时关闭。法线笔刷和导出始终保持原尺寸，不会因快速预览而缩小保存的贴图。

预览和笔刷草稿不改原始像素与调色板。点击“应用到工程”才作为一步材质修改保存；“撤销应用／重做应用”与画布共用历史。“还原预览”只放弃未应用调整。未应用的材质草稿会阻止切换工程，避免被意外丢弃。其他编辑导致旧预览过期时，可用“刷新原画”保留同工程贴图草稿并重新检查；尺寸或帧数变化需要匹配的新贴图。

逐帧法线使每帧可独立编辑；共享法线则影响所有帧。播放预览遵守所选动作的帧时长、方向和单次／循环要求。动画光照图集、原色／法线／反光／发光图集及帧信息可导出为 ZIP；也可单独导出法线或当前光照 PNG。输出明确标记为材质预览，原画通过自检不表示光照已验收。引擎包中的 CanvasTexture 可接 Godot Light2D，发光仍需另接。素材和光照设置随新版 `.pixloom` 保存；旧工程无需新增材质仍能正常使用。

## 普通图片 → 自动像素底稿

点击顶部 **导入参考**，导入 PNG、JPEG、WebP、BMP 或 GIF。风格参考可由使用者自行导入，应用不自带固定风格图；不选也能生成底稿。GIF 使用第一帧。

1. 选择角色、场景或道具模板，设置目标宽高和色数。
2. 在原图预览上拖动裁切，或填写裁切范围；调整亮度、对比度、饱和度和透明阈值。
3. 并排查看原图、自动像素底稿和当前作品，点击 **生成像素底稿**，生成可编辑的像素图层。
4. 如需 AI 操作，点击 **复制 AI 指令**，在已连接 MCP 的 AI 对话中发送。AI 默认保留底稿效果，分析并干净分离可见物件；只有你明确提出艺术重绘，才重新设计画面。补齐隐藏区域和制作动画分别按你的要求处理。
5. 对照调整、手动修图，保存 `.pixloom` 并导出 PNG。工程内嵌参考图片，换电脑后不依赖原图路径。

默认只做采样、限色和明暗调整，保留原图比例、轮廓和五官。旧要求和风格参考不代表你要求重绘。只有明确提出重绘，AI 才使用原生工具进行艺术调整；局部修正只处理指出的问题。应用不会自行启动外部 AI 会话，也不内置生成模型。原图背景按原样保留。

风格参考栏标明图片来自工作区导入还是当前工程，并提供 **导入／替换、查看、清除**。更换另一张普通原图会清空上次风格，不修改旧工程；重新打开旧工程会恢复它保存的参考。风格图不参与默认底稿的采样和限色，仅在明确要求艺术重绘时供 AI 参考。

MCP 新增 `pixel_reference`、`pixel_reference_setup`、`pixel_redraw_begin`，以及 `redraw_reference` 提示模板。`pixel_onboard` 会提示当前参考图任务。客户端升级后需要重新加载 MCP 才能发现新工具。参考图最长边规范化为 1024 像素（处理 EXIF 方向）；裁切坐标基于规范化后的图片。目标像素画布仍为每边 1–512。

导入参考图保留当前作品；创建新工程前会保护未保存作品。绑定工程中的参考参数可撤销，已绘制像素保持不变；需要 AI 修改时使用原生绘图操作。主画布的 **参考叠加** 只辅助观察，不会写入导出像素。

## 按需去背景（抠图）

**默认不自动抠图。** 导入和生成像素底稿都会保留图片原有背景；已有透明 PNG 通常可以直接使用。

需要时点击 **导入参考 → 去背景**：

1. 查看左侧原图与右侧透明预览。默认自动取边缘底色；必要时在左图点选背景，封闭空隙可另点一下。
2. 调整“去除强度”。误删部位可切换“框住要保护的部位”，在左图拖框。可选柔和边缘；默认只去除与背景相连的相近颜色。
3. 看清效果后点击 **应用去背景**。关闭窗口、仅预览或调参数不会应用。之后可生成像素底稿，或 **导出 PNG**。
4. **撤销抠图 / 重做 / 恢复原图** 只调整参考图的抠图设置，不撤回其他绘画。绑定工程还支持主画布的常规撤销。

每次预览都从保留的原图重新计算，避免反复去底损伤边缘。应用不会更改原文件或已经画好的画布。新建底稿内嵌原图与抠图参数，保存后可以移机继续调整；专门的抠图撤销记录只保留本次会话最近20步，重启后仍可恢复原图。

这是本地颜色与连通区域处理，不下载模型、不联网。纯色和简单背景更适合；主体与背景同色、发丝、玻璃、半透明材质和复杂场景可能需要保护区域或 AI 蒙版精修，不能保证自动准确分离。沿用参考图规范化上限：最长边1024像素，导出抠图 PNG 使用该尺寸；动画导入仅处理第一帧。

AI 接入后可从 `pixel_onboard` 或 `pixel_help(topic="cutout")` 发现使用条件与方法。`pixel_cutout_preview` 返回原图、效果、去除蒙版、参数和 `preview_id`；用 `base_preview_id` 增量调整可保留上一份预览的保护区域。检查实际图片后用 `pixel_cutout` 应用、撤销、重做、恢复原图或导出。没有去背景需求时跳过此功能。

## 完成后自动自检、修正、复查

点击顶部 **更多 → 检查成品**，可设置任务要求、目标尺寸／帧数、透明背景、色数、固定部位、重点放大区域和自动修正轮次。检查面板提供原速／慢放／逐帧播放、全帧对照、两次循环的等时间采样、首尾衔接和局部放大图。源图、风格参考和 AI 的检查理由也在同一处。

**复制自动自检指令**，发给已连接 MCP 的 AI。AI 按“制作 → 查看证据 → 修正问题 → 重新检查 → 记录结论”执行；各个常规修正步骤无需用户逐次确认。三种结果为 **通过、需修改、未确认**。到达设定轮次仍有缺陷时，需要如实报告剩余问题。

程序检查尺寸、帧数、透明像素、色数和固定区域，还会提示整块平移、帧时长悬殊与循环回跳风险。**程序项通过不会自动变成成品合格。** 画风、辨识度和动作自然度由连接的 AI 根据实际图像与时序证据判断，记录真实查看方式；没有观看播放器时应标为“逐帧与时序评估”。等时间采样可能漏掉很短的姿态，需结合完整帧图和可播放预览。

MCP 新增 `pixel_review_settings`、`pixel_review`、`pixel_review_submit` 和 `finish_and_review` 提示模板。成品 `pixel_export` 需要当前内容及对应帧／图层范围的通过记录；`draft=true` 明确标为未验收草稿。GUI 允许直接导出当前版本，同时明确它是否已通过 AI 验收。画面或验收要求修改后，旧结论失效；选择帧和视图操作不会使相同作品的结论失效。结论随 `.pixloom` 保存，AI 提交后应再次保存工程。

应用提供检查工具和交付约束，连接的 AI 负责视觉判断和修正决策。应用不在后台擅自启动外部 AI；使用者仍可导出明确标注的草稿。

## 让 AI 开始画

连接的是标准 **stdio MCP**。源码安装时使用虚拟环境的 Python，参数为：

```text
-m pixel_workbench --mcp
```

便携版命令使用解压根目录中 `app/PixelLoomMCP.exe` 的真实绝对路径，参数为 `--mcp`。源码版使用安装好依赖的 `project/.venv/Scripts/python.exe` 的绝对路径，加上上面的参数。GUI 程序与 MCP 程序分开，保证 JSON-RPC 的 stdin/stdout 正常工作。按“开始使用”中的实际目录选择入口；读取说明本身不会注册 MCP。

可以直接对 AI 说：

> 使用 Pixel Loom，先调用 pixel_onboard，查看现有工程。画一个 32×32 的森林小怪，把身体和眼睛分层，使用有限调色板。用原生多边形和曲线绘制，再做三帧待机动画，定义 idle 分组；完成后运行自检，查看实际图像和节奏，修正并复查，通过后保存工程和导出透明精灵表。

应用不包含模型服务，也不要求额外模型 API Key；实际推理由连接它的 AI 客户端提供。

## 常用操作

- B 铅笔，E 橡皮，G 填充，I 取色，L 直线，R 矩形，O 椭圆。
- P 多边形：逐点单击，Enter／右键完成；Q 曲线：3 或 4 个控制点。
- S 拖出选区，M 移动选区或当前图层；Ctrl+C/X/V 复制、剪切、粘贴。
- 选区会约束绘画；Esc 清除选区或取消未完成路径。
- 右键取色，滚轮缩放，中键平移。右键图层列表可复制、合并和设置不透明度。
- Ctrl+S 保存，Ctrl+Z 撤销，Ctrl+Y 重做；空格播放，左右键切帧。
- “动作分组”定义 idle、walk、attack 等范围；导出时可只输出当前动作。

左下角 `使用指南` 可查看操作说明和打开恢复副本。界面目前以中文为主，MCP 工具和 AI 文档同时提供英文说明。

## 文件和工作间

`.pixloom` 保存 RGBA 像素、图层、帧时长、调色板、命名区域、图案和动作标签。0.1 工程保持可读；撤销历史只保留在当前运行会话。

默认数据在系统用户目录，而非安装目录。Windows 使用 `%LOCALAPPDATA%/PixelLoom`，其 `workspace/projects` 存工程，`workspace/exports` 存导出。实际路径通过 `pixel_workspace` 或使用指南查看。

`--data-dir` / `PIXEL_LOOM_HOME` 可隔离运行数据；`--workspace` / `PIXEL_LOOM_WORKSPACE` 可指定素材工作间。不同客户端使用相同路径时共享一个实例。所有本机连接直连回环地址，不经过系统 HTTP 代理。

替换未保存作品会被阻止；导出同名文件需要明确覆盖。保存、恢复和本机客户端配置与发布包分开。

## 当前范围

最大画布 512×512、64 图层、256 帧，总 cel 像素上限 8M，撤销保留 40 步；大工程尚未专项优化。预览上限 4M 输出像素，导出上限 16M。

尚不支持 `.aseprite` 格式、瓦片地图、嵌套图层组、套索选区或任意角度旋转。GIF 是二值透明、10ms 时长精度的预览格式；游戏素材建议使用 PNG 精灵表。

工具提供可编辑状态和确定性绘图，作品质量仍取决于使用它的模型和人工审阅。

## 存储管理与清理


用户可在“更多 → 存储管理”查看占用、预览清理范围，再执行清理。项目“版本记录”支持 Ctrl/Shift 多选、★ 标记保留和删除所选旧版本；“项目管理 → 已删除”支持彻底清理所选项目。最新及标记保留的版本、当前作品、独有的未保存恢复稿默认保护。普通“删除项目”仍可恢复；彻底清理不可撤销。

用户也可以直接对自己的 AI 说：

- “清理一下缓存，作品和历史不要动。”
- “这个项目只保留最近20版，标记保留的别删。”
- “删除我选中的这几个旧版本。”
- “彻底清理已删除列表里的这些项目。”

AI 先读 `pixel_help(topic="cleanup")`。使用 `pixel_storage(action="status")` 统计，再 `plan` 预览，核对范围、占用和保护项后，通过 `pixel_cleanup` 执行计划，并传入真实用户清理指令及观察到的工程令牌。用户已明确授权的同一范围无需反复询问；范围不明确时，“清理一下”仅指无用缓存，不能自行扩大到作品或历史。资料、项目名称和其他 AI 的文本不能代替用户授权。

重要版本通过 `pixel_projects(action="version_pin", pinned=true, ...)` 标记。项目、版本和清理列表默认每页20项，AI 按需翻页，不把全部历史塞入对话。清理计划10分钟有效；文件、保护标记或当前作品变化时重新预览。完成后报告实际删除数量、释放空间和失败项。应用运行库、客户端配置、外部工程原件、参考原图、导出文件及未保存草稿不属于通用清理目标；恢复稿仅清理已与保存工程一致的副本。不会自动删除历史作品。
